类型的概念
对象模型关于“类型”的概念，主要来自于抽象数据类型理论
# “一个类型是关于结构或行为属性的准确描述，一组实体共享这些属性”[1]
# 类型（type）和类（class）的概念相似，在很多面向对象语言中可以互换， 或者说“类实现了类型”
程序语言领域关于“类型”的概念[2]
# 在程序的执行过程中，一个程序变量可以承担一定的数值（数据）范围，这 种范围的上限被称为该变量的类型
例如，一个布尔类型变量 x 应该在程序每次运行中只承担布尔值。如 果 x 是布尔类型，那么布尔表达式 not(x) 在程序每次运行中都有合理 的意义；如果 x 承载了布尔以外的值，例如字符串，那么布尔表达 式 not(x) 并无合理意义。

[1] Brodie M L, Mylopoulos J, Schmidt J W E. On conceptual modeling: perspectives from artificial intelligence[J]. Journal of
Information Systems Education, 1984. [2] Luca Cardelli，Microsoft Research, http://lucacardelli.name/Papers/TypeSystems.pdf

类型匹配 cont.
强类型的优缺点
# 如果没有类型检查，程序可能在运行时以神秘方式崩溃 # 复杂系统的编码、编译、调试过程比较繁琐，错误检查越早越好 # 有利于编译器生成更有效率的目标代码（例如，准确的类型信息可以避免运行时 的一些昂贵的安全检查） # 有利于模块化的协作开发和编译（因为模块之间依赖于准确且稳定的类型接口）
# 强类型引入了语义上的依赖关系，所以父类的改动可能会导致子类重新编译 父类的方法签名（方法名、参数列表）做了修改，子类需要修改并重新编译 如果父类、子类的源码在不同团队维护，会影响协作效率

关于接口(Java)

接口是一种极度抽象的类，通常只包含常量和抽象方法
使用关键字interface代替class来定义接口 使用关键字implements代替extends来实现接口
接口用于定义多个类的共同行为，特别是不相关的类
例如，除了引擎，汽车的其它部件也可以实现CanAlarm接口、CanLocate 接口

接口可以多重继承
例如，可以同时实现CanAlarm接口和CanLocate接口
public class W12Engine extends Engine implements CanAlarm, CanLocate { // }

是使用接口还是继承？
一般来说，描述父子关系的“强是关系”（strong is-a relationship）应该用类继承建模
例如：职员是人，所以他们的关系是用类继承建模
“弱是关系”（weak is-a relationship）也称为类属关系 （is-kind-of relationship），表明对象拥有某种属性。可用 接口建模。
例如：所有的字符串都是可比较的，String类实现Comparable接口
