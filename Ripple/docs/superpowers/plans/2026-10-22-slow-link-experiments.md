# 单服务端低带宽实验实施计划

**目标：** 在原版 Ripple 上完成基础限速、附加延时和附加随机丢包三组真实实验，并提供可复用脚本。

**方案：** 复用 `runner.Experiment` 的隔离网络、真实 JVM、订阅、抓包、收尾与数据库归档；新脚本负责三组参数、60秒检查点、最后收齐时间和逐条哈希核对。修改测试客户端增加纯数字字符串模式和正文哈希事件，不修改 Ripple 业务源码。

**技术栈：** Python 标准库、Java 8、Netty 原版发行包、Linux tc/netem、网络命名空间和 tcpdump。

## 固定条件

- 一个服务端、一个发布客户端、一个订阅客户端，正式组使用 `bandwidth-v0-stable`。原始版本在预备启动中出现已知连接表空指针；共同修复基线保持原版线格式，三组完全一致。
- 每秒1条，持续60秒；每条2048字节，正式正文由数字字符组成，前12位为序号，其余为确定性随机数字。
- 服务端到订阅者下行限速1024字节/秒，反向不限；单位明确采用1024字节。
- 基础组没有额外延时或随机丢包；延时组下行增加2000毫秒；丢包组下行随机丢包50%。
- 2秒是额外传播延时，实际延迟包含排队；丢包作用于网络包。
- 同一随机种子、完全相同的业务消息，无压缩、无紧凑编码。
- 使用TBF限速，1600 B令牌桶突发；额外延时／丢包使用其下的netem队列；以tc实际配置和抓包核对。
- 最多等待1800秒，收齐提前结束；未收齐不冒充永久丢失或内容正确。
