# Ripple 本地实验台

在 Windows 中双击上一级目录的 **启动Ripple实验台.cmd**，浏览器会打开 http://127.0.0.1:8877 。

程序使用本机 `Ripple/` 源码独立构建，启动真实 Java 节点，使用 Linux 网络命名空间和 `tc` 施加网络条件。原项目的 ACK、重连、分发和数据保留逻辑保持原样。

## 使用

1. 选择预设，或增删服务端、发布者和订阅者。每个客户端可以选择首连服务端。
2. 给每位发布者配置消息字节数、每秒发送数、发送时长和随机种子。
3. 添加有向链路，配置带宽、延迟、随机丢包、字节队列，以及定时 100% 丢包故障。反方向需要单独添加。
4. 设置发送结束后继续观察的时间，点击“开始实验”。
5. 系统构建源码、启动节点、提交全部订阅，逐对验证端到端暖机探针；确认后才开始正式负载与网络限制。
6. 在运行页观察每个节点的事件和原始日志，也可打开节点详情页或运行中的原版网页。
7. 结束后在历史页比较多次结果，或下载包含原始记录的 ZIP。

勾选“自动打开各节点详情页”会打开服务端和客户端的独立观测页面；浏览器可能要求允许本地站点弹出窗口。被拦截时，点击节点卡片中的入口即可。原版网页随真实节点结束而关闭；归档的观测页面仍可查看。

## 环境

当前开发与验证环境为 Windows + WSL Ubuntu，已有 Java 8、Maven、Python 3、iproute2、tcpdump、ethtool。Python 后端只使用标准库，网页不需要 npm 安装或 CDN。

新机器需要先准备 WSL2 Ubuntu 和上述工具。启动器默认发行版名称为 `Ubuntu`，可用以下命令指定其他发行版或端口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\ripple_lab\launch.ps1 -Distribution Ubuntu -Port 8877
```

也可以在 Linux / WSL 中直接启动：

```bash
cd /mnt/d/Ripple
sudo python3 -m ripple_lab.server --port 8877
```

直接启动时用 Ctrl+C 正常关闭，控制器会等待实验清理。Windows 双击启动器在后台运行控制服务，关闭网页不会中断实验。界面的“立即结束”会停止本次实验、归档并清理它自己的节点和网络空间。

## 参数与统计口径

- 带宽单位为十进制 **kbit/s**，控制源节点到指定目标 IP 的 IP 流量，包括协议开销与该方向的控制消息。未配置的方向不限速，不表示两端合计的共享带宽。
- 消息大小是原始字符串的 UTF-8 字节数，包含实验发布者和序号标识；随机正文为 ASCII。线上的编码、TCP/IP 开销会额外占用带宽。
- 每位发布者用独立键 `load-<发布者ID>`，每位订阅者订阅所有发布者；避免多个发布者覆盖同一个键影响解释。
- 发送速率是目标调度速率，采用单调时钟。实际提交数量单独计数；机器繁忙或原库同步重连阻塞时跳过发送时隙，避免补发突发负载。
- 到达发送截止时间或点击“停止发送”后不开始新的调用。截止前已进入原库的同步调用可能继续阻塞并稍后写入网络，`sent-*.json` 的 `in_flight` 和 `blocked_slots` 明确记录此边界。
- 等待时长从所有发布者结束调度后开始计算，固定等待，不因“收齐”提前结束。定时故障相对统一发送开始，控制器约每 100 ms 检查一次。
- `send` 是开始调用原版 `put`；`wire_send` 是观察到出站消息；`write` 是 Netty 写回调；三者都不等同订阅者处理成功。
- `put_success` 是发布者收到的成功 PUT 响应，不能作为订阅者成功处理的证明。
- `delivery` 是订阅者原处理器返回成功后记录的事实。`content_ok` 对完整载荷与种子、大小、发布者、序号逐字比对，并保存完整 SHA-256。
- “未观察到”按实际提交数 × 订阅者数减去唯一处理数计算，受观察窗口影响，不能直接称永久丢失。延迟从提交调用前计时至订阅者处理返回，只统计已有样本。
- 新连接上的观察器每 10 ms 安装，首次回调可能早于安装。暖机会验证数据路径；事件队列或关联缓存溢出会显式记录 `observation_gap`，此时应结合日志及抓包复核。
- 抓包和原始业务日志也有开销。最大参数是输入边界，不是这台机器保证可承载的性能；实验结果以实际提交量和缺口告警为准。

## 源码版本与归档

每次实验计算源码和适配器摘要。构建在 Linux 临时缓存目录进行，不改工作区源码或原项目的 `target`，也不回退到旧发行包。源码及构建产物未变时可复用已校验缓存。当前核对的上游提交为 `468e9cb4296110467e3cfdafed412b3dbecfd52a`；以后本地更新源码，下一次实验会自动重新构建。

结果在 `ripple_lab/data/runs/<实验ID>/`：

| 文件 | 用途 |
| --- | --- |
| `state.json`、`runtime.json` | 参数、实际节点地址、构建身份、结果与警告 |
| `events/*.jsonl`、`events.sqlite` | 原始事件与可查询索引 |
| `control/sent-*.json` | 各发布者真实提交数、调度截止及阻塞状态 |
| `logs/` | 构建、节点、抓包和控制器日志 |
| `metrics.jsonl` | 时间序列指标 |
| `tc-start.json`、`tc-end.json` | 内核队列实际配置与统计 |
| `captures/*.pcap` | 各节点 TCP 抓包 |
| `databases/` | 停止后复制的原版数据库快照 |
| `audit.json` | 抓包结构/摘要、内核丢包与数据库完整性检查 |

同一链路两端的抓包不能直接相加计算吞吐；数据库快照受原版历史保留策略影响，行数不是历史总送达数。

## 验证与复现

```bash
python3 -m unittest discover -s ripple_lab/tests -v
python3 -m ripple_lab.tests.network_smoke
python3 -m ripple_lab.tests.integration
```

`network_smoke` 和 `integration` 需要 root。后者需要先运行控制服务，会真实执行正常链路、持续 100% 丢包、丢包恢复和多节点四组实验，并保存 `integration-results.json`；不要与手动实验同时运行。

网页逻辑测试在 Windows 运行：

```powershell
node --test .\ripple_lab\web\*.test.cjs
```

Java 自测在每次适配器首次编译时执行，包含完整内容损坏检测、事件记录、定速与阻塞隔离验证。
